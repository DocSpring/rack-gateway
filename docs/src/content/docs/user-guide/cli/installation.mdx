The `rack-gateway` CLI is distributed as a single binary. Choose the installation method that works best for your platform.

## Install a Release

Releases include builds for macOS on Apple Silicon and for Linux (x86_64 and arm64). Install the latest one with:

```bash
curl -fsSL https://github.com/DocSpring/rack-gateway/releases/latest/download/install.sh | sh
```

The script downloads the build for your machine and checks its SHA-256 checksum. When the GitHub CLI (`gh`) is
installed, it also checks the build provenance attestation: the archive must have been built by the repository's
Release workflow. It installs `rack-gateway` into `/usr/local/bin` when you can write to it, or `~/.local/bin`.

| Variable | Description |
|----------|-------------|
| `RACK_GATEWAY_VERSION` | The release to install, such as `v0.1.29` (default: the latest release) |
| `RACK_GATEWAY_INSTALL_DIR` | Where to install the binary |
| `RACK_GATEWAY_REPOSITORY` | The GitHub repository to install from (default: `DocSpring/rack-gateway`) |

The macOS build supports security keys (WebAuthn). The Linux builds don't: they verify MFA with TOTP, YubiKey OTP or
backup codes. To use a security key from Linux, or to run the CLI on an Intel Mac,
[build from source](#building-from-source).

### Installing by hand

Each release has, for each platform, an archive holding the `rack-gateway` binary, its checksum and its attestation
bundle:

```bash
VERSION=v0.1.29     # see https://github.com/DocSpring/rack-gateway/releases
PLATFORM=linux-amd64  # or linux-arm64, darwin-arm64
BASE=https://github.com/DocSpring/rack-gateway/releases/download/$VERSION
curl -fsSLO $BASE/rack-gateway-$PLATFORM.tar.gz
curl -fsSLO $BASE/rack-gateway-$PLATFORM.tar.gz.sha256
shasum -a 256 --check rack-gateway-$PLATFORM.tar.gz.sha256
gh attestation verify rack-gateway-$PLATFORM.tar.gz --repo DocSpring/rack-gateway
tar xzf rack-gateway-$PLATFORM.tar.gz
sudo install -m 0755 rack-gateway /usr/local/bin/rack-gateway
```

## Verify Installation

```bash
rack-gateway version
```

You should see output like:

```
client: 0.1.29
gateway: (not logged in)
server: (not logged in)
```

## Shell Completion

The CLI supports shell completion for bash, zsh, fish, and PowerShell.

<Tabs>
  <TabItem label="Bash">
    ```bash
    # Add to ~/.bashrc
    source <(rack-gateway completion bash)

    # Or generate a file
    rack-gateway completion bash > /etc/bash_completion.d/rack-gateway
    ```
  </TabItem>
  <TabItem label="Zsh">
    ```bash
    # Add to ~/.zshrc
    source <(rack-gateway completion zsh)

    # Or add to your fpath
    rack-gateway completion zsh > "${fpath[1]}/_rack-gateway"
    ```
  </TabItem>
  <TabItem label="Fish">
    ```bash
    rack-gateway completion fish | source

    # Or save to completions directory
    rack-gateway completion fish > ~/.config/fish/completions/rack-gateway.fish
    ```
  </TabItem>
  <TabItem label="PowerShell">
    ```powershell
    # Add to your PowerShell profile
    rack-gateway completion powershell | Out-String | Invoke-Expression
    ```
  </TabItem>
</Tabs>

## Recommended Alias

Set up a short alias for convenience:

```bash
# Add to ~/.bashrc, ~/.zshrc, or equivalent
alias cg="rack-gateway"
```

Now you can use:
```bash
cg apps
cg deploy
cg logs -a myapp
```

## WebAuthn Support (Optional)

Security keys (WebAuthn/FIDO2) in the CLI need a build with libfido2. Install it before building from source:

<Tabs>
  <TabItem label="macOS">
    ```bash
    brew install libfido2
    ```
  </TabItem>
  <TabItem label="Ubuntu/Debian">
    ```bash
    sudo apt-get install libfido2-dev libudev-dev libusb-1.0-0-dev
    ```
  </TabItem>
  <TabItem label="Fedora/RHEL">
    ```bash
    sudo dnf install libfido2-devel systemd-devel libusb1-devel
    ```
  </TabItem>
  <TabItem label="Arch Linux">
    ```bash
    sudo pacman -S libfido2 libusb
    ```
  </TabItem>
</Tabs>

<Aside type="note" title="WebAuthn is Optional">
WebAuthn support is optional. Without it (the Linux releases, or `task go:build:cli:nofido`), the CLI offers your
other MFA methods: an authenticator app (TOTP), a YubiKey OTP or a backup code.
</Aside>

## Building from Source

If you prefer to build from source:

<Steps>

1. **Prerequisites**
   - Go 1.26 or later
   - Git and [Task](https://taskfile.dev)
   - libfido2 (see [WebAuthn Support](#webauthn-support-optional)), unless you build without WebAuthn

2. **Clone and build**
   ```bash
   git clone https://github.com/docspring/rack-gateway.git
   cd rack-gateway
   task go:build:cli
   ```

3. **Install**
   ```bash
   sudo mv bin/rack-gateway /usr/local/bin/
   ```

</Steps>

### Building with WebAuthn Support

To build with WebAuthn/FIDO2 support, use the default CLI build:

```bash
task go:build:cli
```

### Building without WebAuthn

To build without WebAuthn support (smaller binary, no CGO):

```bash
task go:build:cli:nofido
```

## Updating

```bash
rack-gateway update
```

`rack-gateway update` downloads the latest release for your platform, checks its checksum and its build provenance
attestation (signed by the Release workflow for that release's tag), runs the new binary to check it works, and then
replaces the installed one. `rack-gateway update --check` only reports whether there's a newer release, and
`rack-gateway update --version v0.1.29` installs that release, even an older one.

If you can't write to the directory the CLI is installed in, run `sudo rack-gateway update`. A Linux build from
source with security key support isn't replaced by a release, which has none: rebuild it from source instead.

Once a day, the CLI checks GitHub for a newer release in the background, and after a command, prints a line
suggesting `rack-gateway update` when there is one. Only release builds check, and only when stderr is a terminal:
never when `CI` is set, or for `version`, `update` and `completion`. Set `RACK_GATEWAY_NO_UPDATE_CHECK=1` to turn it
off. The last result is kept in `update-check.json` in the CLI's config directory.

If you built the CLI from source, rebuild it:

```bash
cd rack-gateway
git pull
task go:build:cli
sudo mv bin/rack-gateway /usr/local/bin/
```

## Troubleshooting

### "command not found"

Make sure the binary is in your PATH:

```bash
which rack-gateway
# Should output: /usr/local/bin/rack-gateway
```

If not, either move the binary to a directory in your PATH, or add its location:

```bash
export PATH="$PATH:/path/to/rack-gateway"
```

### Permission denied

Make sure the binary is executable:

```bash
chmod +x /usr/local/bin/rack-gateway
```

### macOS security warning

The install script and `rack-gateway update` download with `curl` and Go, which don't mark the binary as downloaded
from the internet. If you downloaded the archive with a browser, macOS may refuse to run it the first time. Either:

1. Right-click the binary in Finder and select "Open", then click "Open" in the dialog
2. Or run: `xattr -d com.apple.quarantine /usr/local/bin/rack-gateway`
