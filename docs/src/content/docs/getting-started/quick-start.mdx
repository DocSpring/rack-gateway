This guide gets you running locally in about 5 minutes using mock services. You don't need to configure Google OAuth - the mock OAuth server simulates authentication with test users.

<Aside type="tip">
This quick start is perfect for evaluation and local development. For production deployment, see the [Deployment Guide](/deployment/).
</Aside>

## Prerequisites

Make sure you have these installed:

- **mise** - [Install mise](https://mise.jdx.dev/getting-started.html). `mise install` installs the pinned Go, Bun,
  Node and golangci-lint versions from `mise.toml`
- **Docker & Docker Compose** - [Install Docker](https://docs.docker.com/get-docker/)
- **Task** and **Overmind** - [Install Task](https://taskfile.dev/installation/),
  [install Overmind](https://github.com/DarthSim/overmind#installation)

See [System Requirements](/getting-started/system-requirements/) for detailed installation instructions.

## Setup

<Steps>

1. **Clone the repository**

   ```bash
   git clone https://github.com/DocSpring/rack-gateway.git
   cd rack-gateway
   ```

2. **Install tools and dependencies**

   ```bash
   mise install
   task dev-setup   # air, goimports and libfido2 (and Task and Bun if missing)
   go mod download
   cd web && bun install && cd ..
   ```

3. **Configuration**

   `mise.toml` already points everything at the mock services, so there's nothing to configure. Only create a
   `mise.local.toml` for your own overrides: don't copy `mise.local.toml.example` as it is, because its Google
   placeholders would replace the mock OAuth settings.

4. **Start everything**

   ```bash
   task dev
   ```

   This migrates the database, then starts:
   - Gateway API server at `http://localhost:8447`
   - Web UI at `http://localhost:5223`
   - Mock OAuth server at `http://localhost:3345`
   - Mock Convox API at `http://localhost:5443`
   - PostgreSQL and MinIO (for audit anchors) in Docker

</Steps>

## Try It Out

### Web UI

1. Open `http://localhost:5223` in your browser
2. Click **Continue with Mock OAuth**
3. The mock OAuth server shows a user selection screen
4. Choose **admin@example.com**, the one user the dev stack creates (see [Test Users](#test-users) for the others)
5. MFA is required for every user by default, so you land on **Account Security**: enroll an authenticator app
   (any TOTP app works), and then the other pages open

### CLI

<Steps>

1. **Build the CLI and log in**

   ```bash
   task go:build:cli
   ./bin/rack-gateway login staging http://localhost:8447
   ```

   Your browser opens to the mock OAuth server. Select a test user.

2. **Run Convox commands**

   ```bash
   # List apps (from mock Convox)
   ./bin/rack-gateway apps

   # View processes
   ./bin/rack-gateway ps

   # Check rack status
   ./bin/rack-gateway rack
   ```

3. **Set up a convenient alias**

   ```bash
   alias cg="./bin/rack-gateway"
   cg apps
   cg ps
   ```

</Steps>

## What You're Running

The development environment consists of:

| Component | URL | Description |
|-----------|-----|-------------|
| Gateway API | `http://localhost:8447` | Authentication proxy |
| Web UI | `http://localhost:5223` | Admin interface (Vite dev server) |
| Mock OAuth | `http://localhost:3345` | Simulates Google OAuth |
| Mock Convox | `http://localhost:5443` | Simulates Convox rack API |
| PostgreSQL | `localhost:55432` | Database (in Docker) |

### Test Users

The mock OAuth server offers four test users:

| Email | Role | Capabilities |
|-------|------|-------------|
| admin@example.com | Admin | Full access to everything |
| deployer@example.com | Deployer | Deploy apps, manage builds and releases |
| ops@example.com | Ops | Restart apps, manage processes |
| viewer@example.com | Viewer | Read-only access |

The gateway only lets in users it knows, and the dev stack creates just `admin@example.com` (`ADMIN_USERS` in
`mise.toml`). To try the others, add them on the **Users** page as the admin, or seed them in your
`mise.local.toml`:

```toml
[env]
DEPLOYER_USERS = "deployer@example.com"
OPERATIONS_USERS = "ops@example.com"
VIEWER_USERS = "viewer@example.com"
```

## Explore the Features

### User Management

1. Login as `admin@example.com`
2. Go to **Users** in the sidebar
3. Add `deployer@example.com` with the Deployer role
4. Try changing a user's roles

### API Tokens

1. Go to **API Tokens**
2. Create a new token with the CI/CD role shortcut
3. Note a token can't have permissions its owner's role lacks

### Audit Logs

1. Go to **Audit Logs**
2. See all actions you've taken, each recorded before it ran
3. Note that env values are redacted

### Account Security

1. Go to **Account Security**
2. Add a second MFA method, or regenerate your backup codes
3. Click your name at the bottom of the sidebar to see your active sessions

## Troubleshooting

### Port already in use

If you see port conflict errors:

```bash
# Stop all services
task docker:down

# Restart
task dev
```

### Database connection failed

Ensure Docker is running:

```bash
docker ps  # Should show rack-gateway-postgres-1
```

If the container isn't running:

```bash
task docker:reset
task dev
```

### OAuth redirect issues

Make sure you're using the mock OAuth server URLs:
- Gateway: `http://localhost:8447` (not `https`)
- OAuth redirect: `http://localhost:8447/api/v1/auth/web/callback`
- No `mise.local.toml` overriding `GOOGLE_OAUTH_BASE_URL` or `GOOGLE_ALLOWED_DOMAIN`

For more help, see [Troubleshooting](/operations/troubleshooting/).
