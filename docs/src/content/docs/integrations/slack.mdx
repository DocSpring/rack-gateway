Rack Gateway can forward audit log events to Slack. Notifications are routed by **action patterns** that match the audit log `action` field.

## Features

- OAuth-based connection to a Slack workspace
- Every message names the gateway that sent it, so several gateways can share one Slack app
- Channel routing using glob patterns
- Test notifications per channel
- Dedicated deploy approval alert channel (optional)

## Setup

### 1. Create a Slack App

<Steps>

1. Go to https://api.slack.com/apps
2. Click **Create New App** → **From an app manifest**
3. Select your workspace
4. Paste this manifest (update `redirect_urls`)

</Steps>

```json
{
  "display_information": {
    "name": "Rack Gateway",
    "description": "Audit notifications",
    "background_color": "#2c2d30"
  },
  "features": {
    "bot_user": {
      "display_name": "Rack Gateway",
      "always_online": true
    }
  },
  "oauth_config": {
    "redirect_urls": [
      "https://your-gateway-domain.com/api/v1/integrations/slack/oauth/callback"
    ],
    "scopes": {
      "bot": ["channels:read", "chat:write"]
    }
  },
  "settings": {
    "org_deploy_enabled": false,
    "socket_mode_enabled": false,
    "is_hosted": false,
    "token_rotation_enabled": false
  }
}
```

### 2. Configure Environment Variables

```bash
SLACK_CLIENT_ID="your-client-id"
SLACK_CLIENT_SECRET="your-client-secret"
```

The bot token Slack returns is stored encrypted with `COLUMN_ENCRYPTION_KEY` (see
[Column Encryption](/configuration/environment-variables/#column-encryption)). If that key changes,
notifications stop and are reported in the logs until you reconnect Slack.

### 3. Connect via Web UI

<Steps>

1. Log in as an admin
2. Navigate to **Integrations**
3. Click **Connect to Slack**
4. Authorize the app in Slack
5. Configure channel routing

</Steps>

## Channel Configuration

Each channel has:

- A selected Slack channel
- A list of **action patterns** (glob syntax)

### Default Channels

The gateway creates two default channel configs:

**#security**
- `login.complete`
- `login.*_failed`
- `mfa_method.*`
- `user.update_roles`
- `api_token.*`
- `env.*_protected`

**#infrastructure**
- `deploy_approval_request.*`
- `release.promote`

<Aside type="note">
Action names use underscores (e.g., `deploy_approval_request.*`). Use the Audit Logs page to see the exact `action` values.
</Aside>

### Action Pattern Examples

| Pattern | Matches |
|---------|---------|
| `login.*_failed` | `login.oauth_failed`, `login.user_not_authorized` |
| `mfa_method.*` | MFA enrollment events |
| `api_token.*` | API token create/update/delete |
| `env.*_protected` | Protected env var changes and removals (`env.set_protected`, `env.unset_protected`), including refused `--allow-protected` attempts while the step-up window is open |
| `deploy_approval_request.*` | Request create/approve/reject |
| `release.promote` | Release promotions |
| `user.*` | User create/update/delete/lock/unlock |

### Testing

Each channel card includes a **Test** button that sends a test message, naming the gateway, to the selected Slack
channel.

## Deploy Approval Alerts

The Slack integration also supports a dedicated **Deploy Approval Alerts** channel:

- Enable the alert toggle
- Choose a single Slack channel
- The gateway posts deploy approval alerts to this channel regardless of action patterns

## Message Formatting

One gateway runs per rack, and several gateways can post to the same Slack workspace through one Slack app, so
every message names the gateway that sent it. The first line is `Rack Gateway (<RACK_DISPLAY_NAME>)`, linked to the
gateway, and the notification text starts with `Rack Gateway (<RACK_DISPLAY_NAME>): `. Set
[`RACK_DISPLAY_NAME`](/configuration/environment-variables/#convox-rack) on each gateway (for example `Staging` or
`US`); it defaults to `RACK_ALIAS`, then `RACK`. Emails from the gateway use the same name.

Audit event messages then include:

- Action name
- User or API token
- Status
- Timestamp
- Context fields (when available)
- The audit entry's details. For env var changes, values are `[REDACTED]` unless the app lists the key in
  `audit_visible_env_vars`; rack parameter changes name the parameters only. See
  [Secret Redaction](/security/compliance/audit-trail/#secret-redaction).

Example action:

```
Rack Gateway (Staging)
🚀 deploy_approval_request.approved
User: admin@example.com
Status: success
```

Deploy approval alerts start with the same line, and their **View Approval Request** link opens the request on
that gateway.

Values that come from CI or from users (branch, message, names, resources, audit details) are escaped, so they show
as written and can't mention anyone or add links. The pull request and CI build links appear only for `https://`
URLs, and the CI build link names its host. Long messages and audit details are shortened to fit in a Slack message.
